# TravelTrucks — дизайн реалізації

## Мета

Реалізувати з нуля фронтенд вебзастосунку TravelTrucks для оренди кемперів. Результат має максимально точно відтворювати наданий десктопний макет Figma, виконувати всі обов'язкові функціональні вимоги та не містити помилок у консолі.

Джерела вимог:

- Figma: https://www.figma.com/design/6vTbzaB3EPgOreQz2jOJJe/Campers?node-id=48730-474&p=f
- API: https://campers-api.goit.study/docs

## Обсяг

Обов'язкові маршрути:

- `/` — головна сторінка з hero-банером і кнопкою `View Now`;
- `/catalog` — каталог із серверною фільтрацією та довантаженням;
- `/catalog/[camperId]` — деталі кемпера, галерея, відгуки та форма бронювання.

Реалізується десктопна версія відповідно до обов'язкового обсягу ТЗ. Повна адаптивність для планшетів і телефонів не входить до погодженого обсягу.

## Технічний підхід

- Next.js із App Router та TypeScript;
- CSS Modules і глобальні CSS-токени для точного відтворення Figma;
- TanStack Query, зокрема `useInfiniteQuery` для каталогу;
- React Hook Form і Zod для форми та фільтрів;
- Swiper для галереї;
- Sonner для нотифікацій;
- React Icons або SVG-ресурси з макета для піктограм;
- Vitest, Testing Library і Playwright для перевірок;
- ESLint і Prettier для якості коду.

CSS Modules обрано замість Tailwind або готової UI-бібліотеки, оскільки вони дають прямий контроль над точними розмірами, відступами, кольорами, радіусами та станами компонентів без стилістичних обмежень сторонньої системи.

## Архітектура

### Маршрути та рендеринг

- Головна сторінка є переважно серверним компонентом.
- Каталог містить клієнтський інтерактивний модуль із фільтрами та `useInfiniteQuery`.
- Сторінка деталей отримує основну інформацію за `camperId`; інтерактивні галерея та форма ізолюються у клієнтських компонентах.
- Для маршрутів визначаються `loading`, `error` і `not-found` стани там, де вони потрібні.

### Межі модулів

- `app` — маршрути, layouts, metadata, loading/error/not-found;
- `components` — Header, Button, Loader, CamperCard, FeatureBadge та інші повторно використовувані елементи;
- `features/catalog` — форма фільтрів, список, картки та Load More;
- `features/camper-details` — галерея, характеристики, відгуки та бронювання;
- `lib/api` — базовий HTTP-клієнт, endpoint-функції та побудова query-параметрів;
- `types` — TypeScript-моделі відповідей і запитів API;
- `styles` — глобальні стилі й дизайн-токени.

Компоненти мають одну чітку відповідальність. Бізнес-логіка запитів не дублюється в UI-компонентах.

## Дані та API

Базова адреса: `https://campers-api.goit.study`.

Використовуються endpoint-и:

- `GET /campers`;
- `GET /campers/filters` за потреби для доступних значень;
- `GET /campers/{camperId}`;
- `GET /campers/{camperId}/reviews`;
- `POST /campers/{camperId}/booking-requests`.

Підтримувані параметри каталогу:

- `page`;
- `perPage`;
- `location` — нечутливий до регістру пошук підрядка;
- `form` — `alcove`, `panel_van`, `integrated` або `semi_integrated`;
- `transmission` — `automatic` або `manual`;
- `engine` — `diesel`, `petrol`, `hybrid` або `electric`.

Endpoint бронювання приймає `name` і `email`. Реалізація форми дотримується фактичної схеми API та не вигадує поля запиту, яких backend не підтримує.

## Каталог

Фільтри редагуються локально та застосовуються після натискання `Search`. Тип кузова, двигуна й трансмісії мають одиночний вибір. Після застосування фільтрів:

1. значення нормалізуються;
2. активні фільтри синхронізуються з URL;
3. формується query key, що містить увесь набір фільтрів;
4. запускається новий запит із `page=1` і `perPage=4`.

`useInfiniteQuery` визначає наступну сторінку через `page` і `totalPages`. Натискання `Load More` запитує наступні чотири картки з тим самим набором фільтрів. Кнопка приховується, коли наступної сторінки немає. Результати різних наборів фільтрів не змішуються.

Якщо результат порожній, користувач бачить окремий empty state. Помилка запиту має зрозумілий текст і можливість повторити спробу.

Кнопка `Show more` є посиланням на `/catalog/[camperId]`, відкриває деталі у новій вкладці та використовує `rel="noopener noreferrer"`.

## Сторінка деталей

Сторінка показує повну інформацію, доступну в API, без вигаданих характеристик. Зображення відображаються через оптимізований компонент Next.js, а галерея керується Swiper.

Відгуки завантажуються з окремого endpoint. Кожен рейтинг показується у п'ятизірковій шкалі з чіткими активними та неактивними зірками.

Невідомий або відсутній `camperId` переводить користувача у `not-found` стан. Помилки мережі не маскуються під відсутній ресурс.

## Бронювання

Форма:

- має доступні label-и та повідомлення валідації;
- перевіряє ім'я й валідність email до запиту;
- блокує повторне відправлення під час запиту;
- надсилає `name` і `email` на endpoint конкретного кемпера;
- після відповіді `201` показує успішну нотифікацію та очищає поля;
- у разі помилки показує повідомлення, не стираючи введені дані.

## Візуальна відповідність

Джерелом істини для UI є Figma. Під час реалізації фіксуються точні:

- гарнітура, розмір, вага та висота рядка тексту;
- кольори й прозорість;
- розміри контейнерів і колонок;
- відступи, проміжки, радіуси та межі;
- пропорції й обрізання зображень;
- hover, focus, active, disabled і loading стани.

Не додаються декоративні або функціональні елементи, відсутні у макеті чи ТЗ. Фінальна перевірка виконується при десктопній ширині макета шляхом порівняння кожного маршруту з Figma.

## Доступність і семантика

- семантичні `header`, `main`, `nav`, `section`, списки та form controls;
- коректна ієрархія заголовків;
- клавіатурний focus для інтерактивних елементів;
- label-и для полів і доступні назви іконкових кнопок;
- alt-тексти для змістовних зображень;
- достатній контраст згідно з дизайном.

## Metadata

Кожен маршрут має змістовні title і description. Сторінка деталей генерує metadata з назви й опису кемпера. Головний layout визначає базові Open Graph налаштування, favicon і мову документа.

## Стани завантаження та помилок

- loader або skeleton початкового каталогу;
- окремий loading-стан `Load More`, що не приховує вже отримані картки;
- loader сторінки деталей;
- empty state каталогу;
- error state з повторною спробою;
- disabled/loading стан форми;
- успішна й помилкова нотифікації бронювання.

## Перевірка

Автоматичні перевірки охоплюють:

- побудову query-параметрів;
- визначення наступної сторінки;
- скидання пагінації після зміни фільтрів;
- валідацію та відправлення форми;
- п'ятизіркове відображення рейтингу;
- перехід із головної до каталогу;
- серверну фільтрацію;
- `Load More` із чотирма новими картками;
- відкриття деталей у новій вкладці;
- галерею, відгуки та успішне бронювання.

Перед завершенням виконуються typecheck, lint, unit/integration tests, production build і browser-перевірка без помилок у консолі.
